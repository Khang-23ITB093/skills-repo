## 2. Zero AI Footprints in Code & Comments

1. **Never add AI watermarks or generation tags**:
   - ❌ `// Generated by Antigravity`

   - ❌ `/* Created with AI assistant */`

3. **Coding Style**:
   - Write clean, natural, idiomatic code adhering to established project conventions.
   - Avoid generic boilerplates or repetitive commentary that typical AI generators produce.

## 3. Clean Commit Message Standards

### Message Format
Follow the **Conventional Commits** standard written in the voice of a professional software engineer:

```
<type>(<optional-scope>): <imperative description>

[optional body explaining why the change was made]
```

**Allowed Types**:
- `feat`: New feature or capability
- `fix`: Bug fix
- `refactor`: Code restructuring without changing behavior
- `docs`: Documentation updates (README, API docs)
- `test`: Adding or updating test suites
- `chore`: Build scripts, dependencies, project config

### Prohibited Commit Elements
- ❌ **NEVER** include `Co-authored-by:` trailers mentioning AI or agent.
- ❌ **NEVER** include `Signed-off-by: Antigravity` or similar bot sign-offs.
- ❌ **NEVER** write commit messages like `Generated code for ...` or `AI implemented ...`.

### Good Commit Examples
- `feat(p2p): implement direct peer file transfer stream`
- `fix(socket): handle abrupt client disconnection gracefully`
- `refactor(controller): extract chat message parsing into helper method`
- `test(integration): add multi-client socket communication test suite`

## 4. Privacy & Repository Safeguards

### File Exclusion
Ensure internal agent, assistant, or progress tracking files are **never committed or pushed**:
- `.agents/`
- `.gemini/`
- `*.log`
- Scratch or temporary debug scripts

### Staging Best Practices
- **Do not** use `git add .` or `git add -A` blindly without verifying `git status`.
- Always stage specific files:
  ```bash
  git status
  git add src/main/...
  git commit -m "feat: ..."
  ```
- Verify the global gitignore is active:
  ```bash
  git config --global core.excludesfile  # Should point to ~/.gitignore_global
  ```

---

## 5. Standard Workflow Checklist

When performing Git operations:
1. `git status` to inspect modified and untracked files.
2. Verify no `.agents/` or temporary files are staged.
3. Stage only intentional project code and assets.
4. Verify author (`git config user.name` & `user.email`).
5. Commit with a clean, concise, human-style message.
